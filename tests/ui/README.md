# UI tests (Playwright)

Browser journeys against the Compose-served React console (`web` on port 8080). The suite does not start Vite and does not talk to the API on 8000 for page loads — nginx on 8080 serves the SPA and proxies `/api`.

Python deps live in the repo `.venv`. Do not install Playwright into the system interpreter.

## Run

Prerequisites: `.env` present, `docker compose up` with `db`, `api`, and **`web` healthy**, database seeded ([SETUP.md](../../SETUP.md)). Always run pytest from the **repository root**.

Install once, then pick headless or headed:

```powershell
.\scripts\setup-venv.ps1
.\.venv\Scripts\Activate.ps1
```

| Mode | What you see | Command |
|---|---|---|
| Headless (default) | No window. Report at `evidence/ui/report.html` | `python -m pytest -c tests/ui/pytest.ini tests/ui -v` |
| Headed | Chromium opens; five journeys run in front of you | `python -m pytest -c tests/ui/pytest.ini tests/ui -v --headed` |
| Headed + slow | Same window, 400 ms between actions | `python -m pytest -c tests/ui/pytest.ini tests/ui -v --headed --slowmo 400` |

Linux / WSL (headless):

```bash
./scripts/setup-venv.sh
source .venv/bin/activate
python -m pytest -c tests/ui/pytest.ini tests/ui -v
# or: make test-ui
```

For a visible browser on Linux/WSL you still pass `--headed` (needs WSLg or an X server). On Windows use the PowerShell headed command.

`tests/ui/pytest.ini` pins Chromium, keeps the default **headless**, retains traces/screenshots on failure, and writes a self-contained HTML report to `evidence/ui/report.html` (path is relative to the repo root). `--headed` and `--slowmo` only change how Chromium is launched; they do not skip tests. The suite loads repo-root `.env` itself, so `API_KEY` is available even though `-c tests/ui/pytest.ini` makes pytest treat `tests/ui` as its rootdir.

## Environment

| Variable | Default | Role |
|---|---|---|
| `MINIPAY_UI_URL` | `http://localhost:8080` | Console under test (Compose `web`) |
| `MINIPAY_BASE_URL` | `http://localhost:8000` | API used only to arrange a customer for the create-payment journey |
| `API_KEY` / `MINIPAY_API_KEY` | from `.env` | Arrange-only; the browser never sends the key (nginx injects it) |

Override in the shell; values already in `.env` are loaded automatically.

## Journeys

| Test | What it exercises |
|---|---|
| `test_open_home` | `/` renders the dashboard and search box |
| `test_search_existing_transaction_shows_card` | Header search for seed `TXN00000001` → `result-card` |
| `test_create_payment_success` | `/payments/new` with an API-created customer → `success-banner` + `PROCESSING` |
| `test_search_unknown_reference_shows_error` | Unknown ref → `error-banner` |
| `test_create_payment_invalid_amount_shows_validation` | Amount `-1` → `error-amount` containing "greater than 0", still on the form |

Waits use Playwright `expect` auto-waiting. There are no `sleep` calls.

## Page objects and test ids

Open these in a browser (self-contained; no extra server):

| File | When captured | Result |
|---|---|---|
| [evidence/ui/report-before.html](../../evidence/ui/report-before.html) | Form accepted `-1` (no `amount > 0` check). Submit went to the API; `error-amount` never appeared. | **1 failed**, 4 passed — `test_create_payment_invalid_amount_shows_validation` |
| [evidence/ui/report-after.html](../../evidence/ui/report-after.html) | Same suite after restoring `Number(v) > 0` on the create-payment form. | **5 passed** |
| [evidence/ui/report.html](../../evidence/ui/report.html) | Latest green run (same contents as after). Regenerated by the default pytest command. | **5 passed** |

The negative-amount test is the red/green pair. Reproduce locally:

```powershell
# After (current code — all green):
python -m pytest -c tests/ui/pytest.ini tests/ui -v --html=evidence/ui/report-after.html --self-contained-html

# Watch that one journey:
python -m pytest -c tests/ui/pytest.ini tests/ui/test_journeys.py::test_create_payment_invalid_amount_shows_validation -v --headed --slowmo 400
```

Failed test: Playwright writes a trace under `test-results/` (gitignored). Inspect with:

```powershell
python -m playwright show-trace test-results\<test-folder>\trace.zip
```

Rebuild `web` after frontend changes or the browser will hit a stale nginx image:

```powershell
docker compose up -d --build web
```

## CI

- **Smoke on every deploy:** `test_open_home`, `test_search_existing_transaction_shows_card`, `test_create_payment_success`.
- **Full suite:** nightly (all five journeys).
- Image: `mcr.microsoft.com/playwright/python` (matches the pytest-playwright Chromium revision). Run headless, same `-c tests/ui/pytest.ini` command, upload `evidence/ui/report.html` as a build artefact.
- Stack under test: Compose (or the same images in the pipeline) with `web` reachable at `MINIPAY_UI_URL`.

## Troubleshooting

| Symptom | Fix |
|---|---|
| `UI not reachable at http://localhost:8080` | `docker compose ps` — `web` must be healthy, not only `api` |
| `playwright install` / missing browser | `python -m playwright install chromium` inside `.venv`. Linux/WSL: add `--with-deps` |
| `TXN00000001` not on the result card | Seed the database ([SETUP.md](../../SETUP.md) §3) |
| Stale UI (no Search button / no success banner) | `docker compose up -d --build web` |
| Tests hitting 5173 | Default is 8080. Unset any `MINIPAY_UI_URL` pointing at Vite unless you mean to |
| `--headed` but no Chromium window | Run from Windows PowerShell on the machine that can open http://localhost:8080. WSL needs WSLg or an X server |
